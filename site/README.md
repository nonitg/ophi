# Ophi public site

The pre-launch site for **Ophi**, at **https://ophi.app**. A single editorial composition: large type,
an original interactive tooth sculpture, a brief introduction, and an inline waitlist form.
The “Why Ophi?” dialog holds the problem context and cited public evidence; the privacy dialog explains signup data use.
Design decisions and rationale are in `../DESIGN.md`.

## Run and verify

```bash
cd site
pnpm install
pnpm exec next dev --port 3111
pnpm typecheck && pnpm lint && pnpm test
pnpm build
```

Use `http://localhost:3111` for development. Next.js checks the browser origin for development assets.
From the repository root:

```bash
.venv/bin/python scripts/site-screens.py http://localhost:3111
.venv/bin/python scripts/site-states.py http://localhost:3111
```

Browser checks use the local no-write honeypot branch to verify the success screen without creating a real contact.
They do not prove production contact persistence. Unit tests cover the signup server action separately.

## Sculpture

`public/tooth.bin` is an original stylized model generated by `scripts/build-tooth.mjs`.
It is an illustration, not patient data or a clinical model. Rebuild it from `site/` with:

```bash
node scripts/build-tooth.mjs
```

The renderer loads separately from the page. It draws on demand, caps pixel density, suspends while
hidden, supports drag and keyboard rotation, and has an X-ray view. The server-rendered SVG remains
visible when JavaScript, WebGL, or the asset is unavailable. Reduced motion disables entrance animation and rotation easing.

## Paper and light

`public/paper.svg` (grain) and `public/light-wide.svg` / `light-tall.svg` (window light and leaf shadows)
are original procedural art generated by `scripts/build-room.mjs`. Rebuild them from `site/` with:

```bash
node scripts/build-room.mjs
```

## Signup and launch configuration

`app/actions.ts` validates the email and optional clinic software, checks a honeypot and a per-instance
rate limit, then creates a Resend contact. In development without a key, normal submissions are logged
and treated as success; production without a key returns “Signups are not open yet.”

Before publishing:

- Configure `RESEND_API_KEY` and the string contact property `pms` in Resend.
- Configure sender identity and contact information for Ophi. The owner has confirmed there is no
  public mailing address yet; none has been fabricated or displayed. Resolve this before live signup/newsletter launch.
- Configure the production domain `ophi.app`. Canonical and social metadata already use it; changing
  local metadata does not connect DNS or publish the site.
- Verify a real opt-in contact is saved, and unsubscribe behavior, with the owner's own test address.

Vercel root directory: `site`. Next.js framework defaults. Product positioning remains pre-launch:
no invented launch date, customer counts, product screenshots, or approval-rate promises.
