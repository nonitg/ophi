# Ophi public site

The site for **Ophi**, one assistant for every dental patient, at **https://ophi.app**. It tells the company's
vision (`../ophi-phone` `VISION.md`): a hero card where three patients reach Ophi by call, text and their page,
Ophi drawn as one system between patients and records with everyday moments playing through it, the gap between
the record and the patient with Ophi's fix beside each problem, one crown followed through six moments, the
clinic's side as a working miniature, the stages it grows through, and an inline early-access form.
Design decisions and rationale are in `../DESIGN.md` ("Vision site").

## Where the content lives

- `lib/copy.ts`: every word outside the two scripted miniatures.
- `lib/story.ts`: the crown story (steps, beats, the care timeline, record rows) and the real call's words and timings.
- `lib/team.ts`: the team view's patients, what happens to them while watched, and the held request.

The first call in the story is a real conversation with Ophi's phone agent (a scripted test caller, a fictional
patient): `public/calls/book-cleaning.mp3`, exported from the sibling repo by `../ophi-phone/scripts/site_demo_export.py`.
Its words in `lib/story.ts` are the recording's: never edit them. Everything else in the story and the team view is
an illustration, and the page says so.

## Run and verify

```bash
cd site
pnpm install
pnpm exec next dev --port 3111
pnpm typecheck && pnpm lint && pnpm test
pnpm build
```

Use `http://localhost:3111` for development. Next.js checks the browser origin for development assets.
From the repository root:

```bash
.venv/bin/python scripts/site-widths.py http://localhost:3111
.venv/bin/python scripts/site-vision-flow.py http://localhost:3111
.venv/bin/python scripts/site-phone-flow.py http://localhost:3111
.venv/bin/python scripts/site-load.py http://localhost:3111
```

The first measures 20 widths (and X-ray at three): page overflow, text leaving its section, type under 14px. The
second drives the diagram, the story, the real call and the Approve button. The third does the same on a 390x750
touch phone: the menu, each moving picture fitting one screen, a swipe through the story. None submits the signup
form. The last times the homepage and `/demo` on a throttled slow-4G phone; run it against `next start`, not dev.

## Sculpture

`public/tooth.bin` is an original stylized model generated by `scripts/build-tooth.mjs`.
It is an illustration, not patient data or a clinical model. Rebuild it from `site/` with:

```bash
node scripts/build-tooth.mjs
```

The renderer and the mesh (quantized and gzipped, decoded by `lib/tooth-mesh.ts`) load in parallel after the page. It draws on demand, caps pixel density, suspends while
hidden, supports drag and keyboard rotation, and has an X-ray view. The server-rendered SVG remains
visible when JavaScript, WebGL, or the asset is unavailable. Reduced motion disables entrance animation and rotation easing.

## Paper and light

`public/paper.svg` (grain) and `public/light-wide.svg` / `light-tall.svg` (window light and leaf shadows)
are original procedural art generated by `scripts/build-room.mjs`. Rebuild them from `site/` with:

```bash
node scripts/build-room.mjs
```

## Film page

`/demo` holds the 90-second vision film and the waitlist form with two more optional fields (name, phone).
It is shared by link only: no page links to it, it is `noindex`, and it is not in the sitemap.

- The film is a static file, `public/film/ophi-demo.mp4`, and loads only when someone presses play.
- The form runs the homepage signup unchanged (`app/actions.ts`), then `app/demo/actions.ts` emails the name and
  number to `hello@ophi.app`. They are not stored on the Resend contact, so nothing needs setting up in Resend.
- The film is made in the `ophi-phone` repo (`docs/video/README.md`). To refresh it here, from `site/`:

```bash
FILM=../../ophi-phone/docs/video/ophi-demo.mp4
ffmpeg -y -i $FILM -c:v libx264 -preset slow -crf 21 -c:a aac -b:a 128k -movflags +faststart public/film/ophi-demo.mp4
ffmpeg -y -ss 3 -i $FILM -frames:v 1 -vf scale=1600:-1 -q:v 4 public/film/poster.jpg      # what the page shows before play
ffmpeg -y -ss 37.2 -i $FILM -frames:v 1 -vf scale=1200:-1 -q:v 4 public/film/share.jpg   # link previews
```

## Signup and launch configuration

`app/actions.ts` validates the email and optional clinic software, checks a honeypot and a per-instance
rate limit, then creates a Resend contact. In development without a key, normal submissions are logged
and treated as success; production without a key returns “Signups are not open yet.”

Before publishing:

- Configure `RESEND_API_KEY` and the string contact property `pms` in Resend.
- Configure sender identity and contact information for Ophi. The owner has confirmed there is no
  public mailing address yet; none has been fabricated or displayed. Resolve this before live signup/newsletter launch.
- Configure the production domain `ophi.app`. Canonical and social metadata already use it; changing
  local metadata does not connect DNS or publish the site.
- Verify a real opt-in contact is saved, and unsubscribe behavior, with the owner's own test address.

Vercel root directory: `site`. Next.js framework defaults. Vercel skips a push whose last commit doesn't touch
`site/`, even if earlier commits in the same push do, so end a push with a commit inside `site/` (or redeploy). Product positioning remains pre-launch:
no invented launch date, customer counts or outcome promises. The page states where Ophi is going; see "Claims" in `../DESIGN.md`
for what is not yet true of the product.
